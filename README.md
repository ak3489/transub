# Transub 译流

为任意网页视频叠加实时双语字幕的 Chrome / Edge 扩展（Manifest V3）。声音优先在本机用 Whisper 识别，原文与译文以可拖动的字幕层显示在视频上方，并支持导出 SRT / VTT / TXT。

- 本地 ASR：Whisper Tiny / Base / Small，WebGPU 优先、WASM 回退；首次使用需下载模型。
- 远程 ASR：真正实现了 `/v1/audio/transcriptions`（multipart 上传音频、返回文本）的接口；只有 Chat 兼容的 DeepSeek 等不能用于 ASR。
- 翻译：任意 OpenAI 兼容 Chat Completions 接口，可保存多组配置并一键切换。
- 字幕：拖拽定位、字号 / 颜色 / 背景透明度 / 最大宽度 / 隐藏延时均可调，自动跟随网页全屏。
- 导出：完整双语、仅原文、仅译文；SRT / VTT 带时间轴，TXT 可选时间戳。

## 快速开始

要求：Node.js 20+，Chrome / Edge 116+。

```bash
npm install
npm run typecheck
npm run build
```

然后打开 `chrome://extensions`（Edge 为 `edge://extensions`）：

1. 开启右上角「开发者模式」。
2. 点击「加载已解压的扩展程序」，选择本项目下的 `dist/` 目录。
3. 若需处理本地视频文件，在扩展详情中开启「允许访问文件网址」。

修改代码后重新执行 `npm run build`，并在扩展管理页点击刷新。

## 第一次使用：先配好这两处

扩展有**两套彼此独立**的配置，第一次使用时都要确认：

| 配置 | 设置页位置 | 是否必需 | 说明 |
| --- | --- | --- | --- |
| AI 翻译接口 | 「AI 翻译」 | 默认必需 | 需要 Base URL、API Key、模型名称。DeepSeek、OpenAI、硅基流动等 Key 只用于翻译，不能拿去填远程 ASR |
| 语音识别方式 | 「语音识别」 | 必需 | 本地 Whisper 不需要 Key，首次下载模型；远程 ASR 需要接口地址、Key 和模型 |
| 翻译目标语言 | 「通用设置」 | 默认简体中文 | 决定字幕译文语言，不影响语音识别语言 |
| 本地视频文件权限 | Chrome 扩展详情 | 仅处理 `file://` 视频时必需 | 开启「允许访问文件网址」后才能给本地视频加字幕 |
| 字幕样式 | 「字幕外观」 | 可选 | 不改也能正常使用默认样式 |

> 设置页**没有保存按钮**：修改后顶部会显示「保存中…」，变成「已自动保存」后才算真正写入。输入 API Key 后请看到「已自动保存」再关闭设置页。

### 路径 A：本地识别 + DeepSeek 翻译（推荐）

适合大多数用户：音频只在本机识别，只有识别出的文字会发给 DeepSeek 翻译。

1. 按「快速开始」构建并加载 `dist/`。首次安装后设置页通常会自动打开；没有打开就点击扩展图标 → 右上角齿轮。
2. 进入「AI 翻译」：
   - 点击「服务商预设」里的 **DeepSeek**，会自动填入 `https://api.deepseek.com/v1` 和 `deepseek-chat`。
   - 到 DeepSeek 开放平台的 API Keys 页面创建一个 Key，粘贴到「API Key」。
   - 点「测试连接」，看到「连接成功」后再继续；如果失败，先按本节末尾的「测试连接失败怎么办」处理。
   - 确认右上角显示「已自动保存」，并点击「使用此配置」，让配置旁出现绿色圆点 /「使用中」。
3. 进入「语音识别」：
   - 选择「本地 Whisper」。
   - 模型先选 **Tiny**（下载小、见效快）或 **Base**（日常推荐）。
   - 推理设备选「自动」。
   - 能访问 Hugging Face 就保持默认下载源；不能访问就切换为「国内镜像」。
   - 识别语言先选「自动检测」。
4. 打开一个普通网页视频（YouTube、B 站或本地视频），**先让视频播放出声音**。
5. 点击扩展图标，确认「翻译引擎」下拉框是刚配置的 DeepSeek，然后点「开始双语字幕」。
6. 首次使用会下载本地模型，弹窗会显示进度；下载完成后，检测到说话就会产生双语字幕。
7. 字幕出现后可直接拖动位置；悬停字幕条可用按钮调大 / 调小 / 打开设置，或按住 Shift 滚动滚轮快速缩放字号。

### 路径 B：不填任何 Key，先只显示原文

如果只是想确认扩展能不能捕获声音，可以完全跳过 AI Key：

1. 「语音识别」选择「本地 Whisper」，按路径 A 选模型和下载源。
2. 到「通用设置」关闭「启用 AI 翻译」。
3. 打开视频 → 开始双语字幕。此时只显示原文，不产生任何 AI 请求，也不需要 API Key。
4. 想恢复翻译时，回到「通用设置」重新打开「启用 AI 翻译」，并确保已经配置好 AI 翻译接口。

这条路适合先验证音频捕获和本地识别；确认正常后再配置翻译。

### 路径 C：不想下载本地模型

在「语音识别」选择「远程 ASR 接口」，按「远程 ASR 配置」填写 Base URL、API Key 和模型。翻译仍然使用「AI 翻译」中的配置，两处不要填混。

## AI 翻译配置

### 1. 打开设置

首次安装扩展后设置页会自动打开；之后点击扩展图标右上角的齿轮，或弹窗底部的「全部设置 →」。左侧四个栏目分别是「AI 翻译」「语音识别」「字幕外观」「通用设置」。

### 2. 选择要编辑的配置

「AI 翻译」左侧是配置列表，默认已有一组「我的 AI」：

- 点击某一项只是**编辑**它，不代表正在使用。
- 配置名称后的**绿色圆点**和右侧的「使用中」标签才表示当前生效。
- 如果当前编辑的配置不是使用中的配置，点击右上角「使用此配置」。
- 「新建配置」会新建一组配置，但不会自动启用；新建后记得点击「使用此配置」。
- 「复制配置」适合保留常用配置后微调，例如同一家的不同模型。

弹窗顶部的「翻译引擎」下拉框可以在不打开设置页的情况下切换当前配置，切换后对下一次翻译立即生效。

### 3. 填写接口信息

| 字段 | 怎么填 |
| --- | --- |
| 服务商预设 | 点击 OpenAI / DeepSeek / 硅基流动 / 月之暗面 / Groq / Ollama，会填入对应的 Base URL 和模型名；**不会覆盖**配置名称、API Key 和高级参数 |
| API Base URL | 一般填到 `/v1`，例如 `https://api.deepseek.com/v1`。扩展会自动补全 `/chat/completions`；直接填完整的 `/chat/completions` 地址也可以 |
| API Key | 到对应服务商的开放平台创建。Key 只在当前配置中使用；不同服务商的 Key 不能混用。Ollama 等本地接口可留空 |
| 配置名称 | 仅用于自己在列表和弹窗中识别，例如「DeepSeek 主力」 |
| 模型名称 | 必须与服务商控制台完全一致，区分大小写，例如 `deepseek-chat`、`gpt-4o-mini` |
| 温度 / 最大输出 tokens | 可保持默认。字幕翻译建议温度 0.1–0.3，最大输出 800 通常足够 |
| 高级：自定义翻译提示词 | 可选。会追加到系统提示词，用于术语保留、语气或长短控制 |

### 4. 测试连接并启用

1. 填完 Base URL、API Key 和模型后，点击「测试连接」。
2. 成功会显示请求耗时和模型的一小段回复，说明地址、Key、模型名至少能走通 Chat Completions。
3. 失败会显示错误原因。先修正错误，再点一次测试。
4. 测试通过后等待「已自动保存」，确认状态为「使用中」。

**测试连接只测试翻译用的 Chat 接口，不测试语音识别。** 远程 ASR 是否可用，需要实际开始一次字幕才能确认。

### 5. 常见服务商填写示例

| 服务商 | Base URL | 模型示例 | 备注 |
| --- | --- | --- | --- |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` | 仅用于翻译；DeepSeek 没有 ASR 接口 |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` | 需要可访问 OpenAI 的网络环境 |
| 硅基流动 | `https://api.siliconflow.cn/v1` | `Qwen/Qwen2.5-7B-Instruct` | 国内直连；也可以用它的 ASR 服务，但 Key 配置在「语音识别」中 |
| Groq | `https://api.groq.com/openai/v1` | `llama-3.1-8b-instant` | 速度快；模型下线时按控制台替换 |
| 月之暗面 | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` | 使用 Moonshot 的 Key |
| Ollama 本地 | `http://localhost:11434/v1` | `qwen2.5:7b` | Key 留空；先在本机执行 `ollama pull qwen2.5:7b` 并保持 `ollama serve` 运行 |

上表中的模型名会随服务商调整，预设只是快速填入地址和模型，实际可用性以各控制台为准。

### 6. 只显示原文 / 关闭翻译

进入「通用设置」，关闭「启用 AI 翻译」。关闭后不会产生任何 AI 请求，不需要 API Key，字幕只显示原文。重新开启时会恢复使用当前「使用中」的 AI 配置。

### 7. 测试连接失败怎么办

| 错误 | 常见原因 |
| --- | --- |
| 401 / 403 / 未授权 | API Key 为空、填错、过期，或使用了另一家服务商的 Key |
| 404 / 模型不存在 | Base URL 路径不对，或模型名称拼写错误；确认 Base URL 填到 `/v1`，模型名与控制台一致 |
| 网络请求失败 / 超时 | 网络无法访问该服务、代理异常，或本地服务（如 Ollama）没有启动 |
| 返回内容为空 | 接口地址可能指向了非 Chat Completions 服务，检查 Base URL |

API Key 与配置以明文保存在浏览器扩展存储中，不会上传到扩展作者的服务器，但请勿在共享电脑上保存长期 Key。

## 本地 Whisper 配置

本地模式不需要 API Key，音频不离开设备。扩展在浏览器内通过 transformers.js + ONNX Runtime 运行 Whisper，模型来自 `onnx-community/whisper-tiny`、`whisper-base`、`whisper-small`。

### 1. 打开本地模式

点击扩展图标 → 右上角齿轮进入设置 →「语音识别」→ 在「识别方式」中选择「本地 Whisper」。设置会自动保存，不需要额外点保存按钮。

### 2. 选择模型

| 模型 | 参数规模 | 首次下载约 | 适合场景 |
| --- | --- | --- | --- |
| Tiny | 39M | 40–75 MB | 速度最快，准确率一般；配置较低的电脑或只要求实时性时使用 |
| Base | 74M | 80–150 MB | 速度和准确率较均衡，推荐日常使用 |
| Small | 244M | 250–500 MB | 更准确，但对 GPU / CPU 要求高，实时性可能下降 |

实际下载体积会随量化格式和模型仓库文件变化。初次使用建议先用 Tiny 或 Base 跑通，再按机器性能切换到 Small。

### 3. 选择推理设备

| 选项 | 行为 |
| --- | --- |
| 自动（推荐） | 浏览器支持 WebGPU 时优先使用 GPU；初始化失败会自动回退到 CPU（WASM） |
| WebGPU | 强制使用 GPU 推理，速度通常更快，适合 Base / Small；需要浏览器、显卡和驱动支持 |
| WASM | 使用 CPU 推理，兼容性最好但速度较慢；WebGPU 无法使用或字幕不显示时可手动选择 |

切换模型或推理设备后，需要先停止当前字幕再重新开始，新配置会在下一次会话加载。若日志提示 WebGPU 不可用并回退，属于正常兜底，不代表扩展出错。

### 4. 选择模型下载源

- **Hugging Face**：默认源，需要网络可访问 `huggingface.co`。
- **国内镜像（hf-mirror）**：无法直接访问 Hugging Face 时使用，下载后仍然缓存在本地。

首次开始字幕时会显示「正在加载本地 Whisper 模型」及下载进度，下载期间请保持浏览器运行并不要停止会话。模型加载完成后会缓存在浏览器为扩展分配的缓存中，之后启动通常可以直接读取。

以下情况会导致模型需要重新下载：

- 在浏览器设置中清理了该扩展的站点数据 / 缓存；
- 卸载并重新安装扩展；
- 更换了 Chrome 用户配置或浏览器。

### 5. 选择识别语言

「识别语言」指视频中**正在说的语言**，不是译文目标语言。翻译目标在「通用设置」中单独选择。

- 语言不确定或视频包含多语言：选「自动检测」。
- 单一语言视频：明确指定中文、英语、日语等通常更准确，也能减少语种误判。
- 译文语言不受这里影响。

### 6. 开始识别

1. 打开有视频的网页并开始播放，确保视频本身有对白声音。
2. 点击扩展图标 →「开始双语字幕」。
3. 首次使用等待模型下载 / 加载完成；状态会显示加载阶段。
4. 扩展按语音活动切分音频，检测到说话后逐段识别并翻译。静音、纯音乐或音量过低时可能不会产生字幕。
5. 需要结束时点击「停止字幕」。

识别结果依赖 VAD 切分，通常会有数秒延迟；这不是逐字实时流式识别。对白清晰、背景噪声低的视频效果最好。

### 7. 本地 Whisper 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 一直停在「正在下载模型」 | 切换「模型下载源」为国内镜像；确认网络 / 代理可访问对应域名后重新开始字幕 |
| 提示 WebGPU 不可用 | 保持「自动」让它回退 WASM，或手动选择 WASM；也可更新浏览器和显卡驱动 |
| 字幕出现很慢或断断续续 | 换用 Tiny / Base、优先 WebGPU、关闭占用较高的其他标签页；Small 在 CPU 上通常难以实时 |
| 完全没有字幕 | 确认视频有对白且在播放；DRM 视频、iframe 播放器、静音片段可能无结果；刷新页面后重试 |
| 识别语言不对 | 在「识别语言」中手动指定视频语言，不要依赖自动检测 |
| 改了模型 / 设备但没变化 | 停止当前字幕后重新开始；配置只在新的捕获会话中生效 |
| 模型每次都要重新下载 | 检查是否清理了扩展缓存、使用了不同的浏览器用户配置，或处于无痕模式 |

## 远程 ASR 配置

远程模式适合不想下载本地模型、设备性能有限，或已有 faster-whisper 等自建识别服务的情况。远程 ASR 与翻译配置互相独立，例如可以「硅基流动 ASR + DeepSeek 翻译」。

远程接口必须真正实现 `POST /v1/audio/transcriptions`：接受 multipart 文件上传（本扩展发送 `file`、`model`、`response_format=json`，指定语言时附加 `language`），并返回包含 `text` 的 JSON。**只兼容 Chat Completions 不等于支持 ASR。**

### 配置步骤

1. 设置 →「语音识别」→「识别方式」选择「远程 ASR 接口」。
2. **ASR Base URL**：一般填到 `/v1` 即可，扩展会自动补上 `/audio/transcriptions`。如果服务路径不标准，也可以直接填完整的 `.../audio/transcriptions` 地址。
3. **ASR API Key**：以 `Authorization: Bearer <key>` 发送；本地服务可留空。
4. **ASR 模型**：填写供应商控制台中的准确模型名，区分大小写。
5. **识别语言**：不确定时保持「自动检测」。
6. 播放视频 → 开始字幕。每个语音片段都会上传一次，网络延迟会直接影响出字幕速度。

设置页的「测试连接」测试的是翻译用的 Chat 接口，不会验证 ASR。远程 ASR 是否可用需要实际开始一次字幕才能确认。

### 支持该接口的供应商

| 供应商 | Base URL 示例 | 模型示例 | 说明 |
| --- | --- | --- | --- |
| OpenAI | `https://api.openai.com/v1` | `whisper-1`、`gpt-4o-mini-transcribe` | 标准 OpenAI 转写接口 |
| Groq | `https://api.groq.com/openai/v1` | `whisper-large-v3-turbo`、`whisper-large-v3` | 速度快，有免费额度，适合实时字幕 |
| 硅基流动 | `https://api.siliconflow.cn/v1` | `FunAudioLLM/SenseVoiceSmall` | 国内直连，中文效果好，适合搭配 DeepSeek 翻译 |
| Mistral | `https://api.mistral.ai/v1` | Voxtral 系列 | 模型名与可用性以控制台为准 |
| Together AI | `https://api.together.xyz/v1` | Whisper 系列 | 是否开放 STT 以账户和控制台为准 |
| Fireworks | `https://api.fireworks.ai/inference/v1` | Whisper 系列 | 模型名以控制台为准 |
| DeepInfra | 完整地址 `https://api.deepinfra.com/v1/openai/audio/transcriptions` | Whisper 模型 | 路径不标准，建议直接填完整 endpoint |
| OpenRouter | `https://openrouter.ai/api/v1` | 模型页中的 STT 模型 | 聚合平台，模型与计费变动较快 |
| 自建服务 | 如 `http://localhost:8000/v1` | 任意兼容模型 | Speaches、LocalAI、faster-whisper 的 OpenAI 兼容网关均可 |

供应商的模型名、路径和开通状态会变化，以各自控制台文档为准。上表列出的是典型组合，不代表永久可用。

### DeepSeek 不能用于 ASR

DeepSeek 的开放 API 目前只有对话 / 推理接口，没有音频上传和 `/v1/audio/transcriptions` 端点。把 `https://api.deepseek.com/v1` 填到「远程 ASR」会在启动时报错（通常是 404）。

正确用法是：

- **AI 翻译**：选 DeepSeek，填入 DeepSeek API Key；
- **语音识别**：选本地 Whisper，或远程 ASR 填入 Groq / 硅基流动等其他服务；
- 两者可以同时使用，互不冲突。

### 其他不能直接使用的情况

| 服务 | 原因 |
| --- | --- |
| Kimi / Moonshot | Kimi-Audio 是开源模型，但开放平台没有公开的音频转写端点 |
| Ollama | 本地对话模型服务，没有 `/audio/transcriptions`；能聊音频的模型也不等于提供转写接口 |
| 阿里百炼 Qwen3-ASR | 有「OpenAI 兼容」模式，但走 `chat/completions` + 公网音频 URL，不是本扩展的文件上传格式，直接填会失败 |
| Azure OpenAI | 地址包含 deployment、鉴权用 `api-key`，还需要 `api-version`，不能只替换 Base URL |
| Gemini / Claude 原生 API | 不提供 OpenAI 的音频转写协议，需要自建或使用兼容网关转换 |

### 远程模式注意事项

- 音频片段会上传到所填服务，请确认信任该服务并了解其计费方式。
- 部分 ASR 服务不支持 `language` 参数；如果出现 400，可先把识别语言改为「自动检测」再试。
- 网络抖动会直接表现为字幕延迟或片段失败，建议优先使用地理上较近的服务。
- ASR API Key 同样以明文保存在扩展存储中，不要保存不信任的长期密钥。

## 开始字幕、调整与导出

### 开始前检查

- 当前页面是普通网页。`chrome://`、`edge://`、扩展商店、浏览器内置页面无法注入字幕。
- 视频已经在播放，并且确实有人声对白。纯音乐、静音片段、音量过低的内容不会产生有意义的结果。
- 本地视频需要在扩展详情页开启「允许访问文件网址」。
- 如果开启 AI 翻译，确认「AI 翻译」里有一组「使用中」的配置，并且填好了 API Key。
- 如果只想先看原文，到「通用设置」关闭「启用 AI 翻译」，这样不需要任何 AI Key。

### 启动

1. 打开视频页面并开始播放。
2. 点击工具栏中的扩展图标。
3. 如果弹窗提示「另一标签页正在生成字幕」，说明同一时间只能运行一个会话。先导出原会话字幕，或点击「停止并在此页开始」。
4. 点击「开始双语字幕」。

状态含义：

| 状态 | 含义 |
| --- | --- |
| 正在准备音频… | 正在连接当前标签页的音频 |
| 加载本地模型… / 模型加载 x% | 首次下载并初始化本地 Whisper，等待即可 |
| 聆听中 | 音频捕获正常，正在等待检测到说话 |
| 识别中… | 正在处理一个语音片段 |
| 翻译中… | 原文已识别，正在等待 AI 返回译文 |
| 翻译失败 / 出错 | 在弹窗和最新字幕区域查看具体错误，按下文排错 |

本地模型首次下载可能持续较久；下载完成后会缓存，下一次会话启动会快很多。字幕不是逐字出现，而是检测到一段语音并完成识别后成句出现，因此通常有几秒延迟。

### 字幕操作

- 鼠标移到字幕条上会显示控制按钮，可直接拖动字幕条改变位置。
- 悬停时可以用 `+` / `-` 调整字号，或点击齿轮打开设置。
- 在字幕条上按住 **Shift 并滚动滚轮**，可以快速缩放中英文字号。
- 「字幕外观」中可以调整字体、字号、最大宽度、颜色、背景不透明度、隐藏延时和位置。
- 隐藏延时设为 `0` 时，字幕会一直显示到下一句出现。
- 「原文」和「译文」可以分别隐藏；两项都隐藏时页面不显示字幕。
- 「恢复默认位置」可把字幕重置到画面底部。

所有样式修改会实时同步到已经打开的视频页面，不需要重新开始字幕。

### 停止、切换与刷新

- 点击「停止字幕」后，当前标签页的本次字幕记录仍保留，可以继续在弹窗中导出。
- 修改**语音识别**的模型、设备、语言或远程接口后，需要停止再重新开始字幕，新设置才会生效。
- 修改**AI 配置**或切换弹窗中的「翻译引擎」，会对下一次翻译立即生效，不需要重开会话。
- 在另一个标签页开始字幕会停止当前会话并替换当前记录，**请先导出旧字幕**。
- 页面刷新或站内跳转后，扩展会尝试重新注入字幕层，但视频播放会中断。已经生成的字幕仍保留在当前标签页的会话中，可继续导出；如果状态显示音频已结束或不再出现新字幕，重新点击「开始字幕」。
- 关闭当前标签页或重启浏览器后，会话记录可能无法再导出，重要字幕请提前导出。

### 导出

字幕产生第一条后，弹窗会显示「导出字幕」卡片。导出条件：

- 当前标签页有至少一条完成或进行中的字幕；
- 停止字幕后仍可导出，但不要先在另一个标签页开始新会话；
- 仅导出译文时，需要等待翻译完成，翻译中的条目不会被写入文件。

| 选项 | 说明 |
| --- | --- |
| SRT | 带时间轴，最常见的字幕格式 |
| VTT | 带时间轴，适合网页播放器 |
| TXT | 纯文本；可勾选「在 TXT 中包含时间戳」，不勾选则只有文本 |
| 双语字幕 | 每段同时写原文和译文 |
| 仅译文 | 只写译文；翻译未完成时可能提示暂无可导出内容 |
| 仅原文 | 只写识别出的原文 |

点击「导出 SRT / VTT / TXT」后，浏览器会弹出保存对话框，文件名默认来自当前页面标题。SRT / VTT 的时间轴从开始捕获时视频的播放进度计算；中途暂停、拖动进度条会导致后续时间轴偏移。

## 配置与启动排错

| 现象 / 提示 | 处理方式 |
| --- | --- |
| 加载扩展时提示找不到 manifest | 确认已执行 `npm run build`，并选择 `dist/` 文件夹；不要加载项目根目录或 `public/` |
| 开始按钮灰色或显示「此页面不支持字幕」 | 当前是浏览器内置页、扩展商店或受限制页面，换一个普通视频网页 |
| 提示「请先在设置中完善 AI 翻译配置」 | 「AI 翻译」的 Base URL 或模型名为空；补全或关闭「启用 AI 翻译」 |
| 有原文但译文显示「翻译失败」 | 最常见是 API Key 为空或填错，也可能是额度耗尽；回到 AI 配置点「测试连接」 |
| 测试连接成功，实际字幕仍翻译失败 | 确认真正「使用中」的是刚测试的配置；等待「已自动保存」；检查账户额度和限流 |
| 远程 ASR 报 401 / 404 / 模型不存在 | ASR 配置和翻译配置是分开的；检查 ASR 的 Base URL、Key、模型。DeepSeek 不支持 ASR |
| 一直停在模型加载 / 下载失败 | 「模型下载源」切换到国内镜像，检查网络后重新开始字幕 |
| 状态是「聆听中」但一直没有字幕 | 确认视频有对白且在播放；DRM 视频、iframe 播放器、纯音乐可能无结果；换普通网页试试 |
| 全屏后看不到字幕 | 浏览器原生 `<video>` 全屏无法叠加网页元素；退出原生全屏，使用播放器网页自身的全屏按钮 |
| 改了语音识别设置但没变化 | 停止当前字幕，再重新开始；设置页顶部需显示「已自动保存」 |
| 弹窗提示「另一标签页正在生成字幕」 | 同一时间只支持一个会话；停止旧会话或先导出 |
| 导出卡片没有出现 | 当前标签页还没有字幕；先开始字幕并等到至少一条结果。导出要在对应的原标签页进行 |
| 导出「仅译文」失败 | 翻译还在进行中，等待全部完成后再导出，或先导出双语 / 原文 |
| 提示「无法在此页面注入字幕层」 | 刷新页面后重试，或换一个普通网页；文件视频需开启文件网址访问权限 |

如果问题仍无法定位：打开 `chrome://extensions`，在 Transub 卡片中找到「Service Worker」并点击进入 Console；先复现一次，再查看红色报错。提交问题时请附上报错文本和页面类型，**不要粘贴 API Key**。

## 架构

```
弹窗 / 设置页 (React)
        │ chrome.runtime 消息
        ▼
Service Worker（后台）
  ├─ 会话生命周期、状态持久化（storage.session）
  ├─ 翻译队列：串行调用 AI，流式回填译文
  ├─ 导出：SRT / VTT / TXT → chrome.downloads
  └─ 与内容脚本、离屏文档通信
        │ streamId / START_CAPTURE
        ▼
离屏文档（offscreen document）
  ├─ tabCapture 音频流（并回放，保证标签页仍有声音）
  ├─ AudioWorklet 能量 VAD 切分 → 16 kHz PCM → WAV
  ├─ 本地 Whisper（transformers.js + ONNX Runtime WebGPU/WASM）
  └─ 远程 ASR（audio/transcriptions）
        │ ASR_SEGMENT
        ▼
Service Worker → 翻译 → 内容脚本
        ▼
内容脚本：Shadow DOM 双语字幕悬浮层
  ├─ 挂载到全屏容器，监听 fullscreenchange
  ├─ 拖拽 / 自动重挂载 watchdog
  └─ 字幕样式实时同步
```

### 关键设计

- **离屏文档持有音频**：MV3 Service Worker 不能持有 `MediaStream` / `AudioContext`，因此由 offscreen document 完成采集与 ASR；后台只做编排。
- **音频回放**：捕获标签页音频后，离屏文档将同一路音频接回输出，避免开始字幕后视频静音。
- **串行翻译队列**：识别片段按顺序翻译，避免并发请求乱序；流式响应会持续更新当前字幕的译文。
- **时间轴**：片段以「开始捕获」为零点。启动时读取视频 `currentTime` 作为 `baseTime`，导出时加到每个片段上，使时间轴尽量贴近原视频。
- **样式单一来源**：内容脚本、设置页预览、弹窗共享同一份设置数据（`chrome.storage.local`），修改后即时广播。

## 隐私

- 扩展只捕获当前标签页正在播放的音频，不请求麦克风权限。
- 本地识别模式下，音频不上传；识别出的**文字**会发送给你配置的翻译服务。
- 远程 ASR 模式下，音频片段会上传到你填写的 ASR 服务。
- API Key（翻译与 ASR）和设置以明文保存在浏览器扩展存储中（`chrome.storage.local`），不会同步到云端，但本机其他可读取扩展数据的程序可能看到。请勿在共享电脑上保存长期 Key。
- 本地 Ollama 等自建服务是否可用取决于其 CORS / 网络配置。

## 已知限制

- **同一时间只支持一个标签页、一个会话**。在另一个标签页启动会先停止原会话。
- **DRM 内容**：Netflix 等受保护视频的音频可能无法被捕获（表现为无声音或无声片段），且受保护视频层可能无法叠加字幕。这是浏览器 / DRM 限制，不是所有影片都能使用。
- **原生视频全屏**：浏览器原生 `<video>` 全屏时，网页无法在其上绘制任何元素。YouTube、Bilibili 等使用容器全屏通常正常；遇到原生全屏请退出全屏或使用网页播放器模式。
- **时间戳漂移**：字幕时间以开始捕获为基准。中途暂停、拖动进度条、切换视频后，导出时间轴会与被拖动后的视频进度不一致。建议从视频开头附近启动，或重新开始会话。
- **换页 / 刷新**：刷新或站内跳转通常会结束音频捕获，已生成的字幕仍保留在标签页会话中可导出；要继续生成需重新点击「开始字幕」。
- **iframe 内视频**：内容脚本未注入子框架（`all_frames: false`），嵌入在 iframe 中的播放器可能无法显示字幕。
- **识别质量**：本地 Tiny 模型速度快但准确率有限；背景音乐、多人重叠说话、强噪声会明显降低识别效果。VAD 会跳过静音片段，纯音乐不一定产生字幕。
- **首次模型下载**：约 40 MB 至数百 MB，取决于模型；下载期间需保持页面打开。国内网络可在设置中切换 hf-mirror。
- **性能**：本地 Small 模型 + WASM 回退可能无法实时跟上语音；WebGPU 可用性和驱动相关。
- **翻译延迟**：取决于所配置 API 的速度与网络，字幕通常比原声晚 1–3 秒。
- **网站改版**：依赖通用 DOM 定位视频与全屏容器，极端自定义播放器可能无法自动挂载，可刷新后重试。
- **导出为参考时间轴**：翻译字幕与原文同一时间段显示，不提供逐词时间戳。

## 后续扩展

当前结构为后续功能预留了清晰边界：

- **配音 / TTS**：在 `background` 翻译队列产出译文后，增加 TTS 请求，由离屏文档播放合成音频，并做闪避（ducking）压低原声。
- **更多 ASR**：在 `offscreen` 增加引擎实现，保持 `OffscreenRequest` / `OffscreenEvent` 协议即可。
- **术语表 / 上下文**：`AiProfile.customPrompt` 已进入翻译请求，可扩展为术语表与前后文窗口。
- **多会话**：后台目前刻意限制单会话；若需多标签页，可将会话状态改为按 tabId 索引，并为每页创建独立离屏音频图。
